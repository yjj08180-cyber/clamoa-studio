# 클라모아 인스타그램 콘텐츠 제작 워크플로우

2026-11-23 · 운영 기준 및 Codex 웹사이트 MVP 구현 명세

클라모아 팀은 시즌 신호를 조사하고, 그중 시각적으로 풀 수 있는 주제를 골라 패션·뷰티·아트 이미지를 미리 제작한다. 이미지는 프로젝트별로 쌓아두고 발행 시점에 여러 시즌과 장르를 섞어 피드를 편집한다. 웹사이트에서 가장 중요한 단위는 **컷 한 장**이다. 각 컷에서 선정 이유, 무드 레퍼런스, 사용한 로고, 생성 버전, 최종 선택본까지 거슬러 볼 수 있어야 한다.

## 1. 현재 제작 방식

| 단계 | 입력 | 작업과 판단 | 결과물 |
|---|---|---|---|
| ① 브리프 받기 | 시즌, 필요한 수량, 브랜드 로고, 기존 피드 또는 보드 | 새 방향을 탐색할 때는 좋아하는 컷과 어색한 컷을 하나씩 고르고 이유를 듣는다. 기존 시리즈를 확장할 때는 기준 컷 번호와 바꿀 요소만 받는다. | 제작 브리프 |
| ② 주제와 근거 고르기 | 컬러 전망, 런웨이 자료, 브랜드·스튜디오 원문, 필요시 검색·판매 데이터 | 키워드별로 출처·시즌·관찰 내용·선정 이유를 적는다. 전망, 런웨이 관찰, 실측 수치는 구분한다. 수치를 쓸 때만 기간·지역·단위를 함께 기록한다. | 출처와 선정 이유가 붙은 주제 카드 |
| ③ 무드보드 구성하기 | 선택한 주제, Pinterest 핀, 사진가·아티스트·글로벌 스튜디오 작업 | 참고한 요소를 빛·색·질감·프레이밍으로 나눠 적는다. 새 컷에서는 피사체, 배경, 동작, 오브제 사이의 관계를 다시 설계한다. | 출처와 시각적 관찰이 짝지어진 레퍼런스 보드 |
| ④ 컷 리스트 짜기 | 브리프, 주제 카드, 보드 | 컷마다 주인공·한 가지 시각적 아이디어·거리·조명·로고 가공 방식을 정한다. 전신과 접사, 여백과 밀도, 인물과 정물의 반복을 살핀다. | 번호가 고정된 컷 리스트 |
| ⑤ 한 장씩 생성하기 | 컷별 프롬프트, 해당 로고 파일 | ChatGPT Image에서 컷마다 독립된 세로 4:5 이미지를 생성한다. 각 요청에 그 컷의 로고를 직접 연결하고 결과를 컷 번호에 기록한다. | 컷별 생성 원본과 버전 |
| ⑥ 전체·확대 검수하기 | 한눈에 보는 번호 보드, 개별 원본 | 보드에서는 중복·톤·리듬을, 원본에서는 로고 철자·형태·원근·질감·불필요한 문자를 확인한다. 수정할 요소를 특정해 해당 컷만 다시 생성한다. | 선택본, 보류 사유, 수정 이력 |
| ⑦ 보관하고 조합하기 | 선택본과 보류본 | 개별 이미지를 콘텐츠 풀에 쌓고 색·소재·장르·컷 번호로 찾는다. 발행 후보를 피드에 임시 배열하고 빼거나 순서를 바꾼다. | 콘텐츠 풀과 피드 배열안 |
| ⑧ 내보내기 | 선택한 컷 또는 배열안 | 생성 원본은 보존하고 게시용 1080 × 1350 JPG를 만든다. 개별 컷과 번호가 표시된 전체 보드를 묶는다. | 개별 JPG, 인덱스 JPG, ZIP |

**기존 운영과 웹 구현의 경계** — 이번 시즌에는 컷별 생성, 검수, 20장 묶음 내보내기를 수행했다. 아래의 검색 가능한 콘텐츠 풀, 드래그 방식 피드 편집, 작업 재개와 버전 비교는 이 과정을 웹에서 운영하기 위한 기능 요구사항이다.

## 3. 컷 브리프와 생성 규칙

웹 폼과 프롬프트 생성기가 같은 필드를 사용한다. 아래는 실제 08번 연출을 재현하기 위한 입력 예시다.

```yaml
shot_number: "08"
title: "Celestial Handle"
season: "2027 S/S"
theme: "Energy Orange"
editorial_reason: "오렌지를 가죽과 구리의 고유색으로 보여준다."
subject: "코냑색 가죽 가방"
scene: "구리 링과 가방 손잡이의 곡선이 겹친다."
light: "옆에서 들어온 빛이 가죽 결을 스치고 둥근 그림자를 만든다."
framing: "세로 4:5, 정물 근접 촬영, 가방 앞면이 보이는 각도"
logo:
  asset: "프로젝트에서 선택한 clamoa 워드마크 파일"
  placement: "가방 앞면 오른쪽 아래"
  process: "무색 음각"
  detail: "획 안쪽에도 가죽의 결이 이어지고 눌린 가장자리에만 그림자가 생긴다."
review_note: "작은 화면에서 가방 실루엣이 읽히고 확대 시 음각이 선명해야 한다."
```

**프롬프트 조립 순서** — 이미지 용도와 비율 → 피사체와 동작 → 소재와 색 → 카메라 거리와 빛 → 로고 파일·위치·가공 → 한 장의 독립된 사진으로 출력. 담당자가 완성 문장을 편집할 수 있게 하고, 실제 생성에 사용한 문장을 버전별로 저장한다.

**로고 기준** — 소문자 여섯 글자 `clamoa`, 긴 `l`, 단층형 `a`, 글자 간격을 확인한다. 구두에는 작은 흰색 인쇄, 가죽에는 음각, 금속에는 각인, 유리에는 에칭, 의류에는 직조 라벨처럼 소재가 허용하는 가공을 정한다. 이번 시안은 첨부 로고를 재구성한 가이드를 사용했다. 웹에서는 등록 자산에 ‘공식 원본’과 ‘시안용 가이드’를 표시하고, 공식 자형 일치가 필요한 컷은 마스터를 직접 배치한 보정본을 최종 버전으로 등록할 수 있게 한다.

## 4. 웹사이트 MVP의 화면과 데이터

| 화면 | 사용자가 할 수 있는 일 | 저장할 데이터 |
|---|---|---|
| 프로젝트·브리프 | 시즌과 목표 수량 입력, 기존 컷으로 시작, 로고 등록 | 프로젝트명, 시즌, 수량, 무드 메모, 로고 자산 ID와 유형 |
| 리서치·무드보드 | 키워드와 출처 URL 등록, 썸네일과 관찰 메모 모으기, 선정한 주제를 컷에 연결 | 주제 ID, 근거 유형, 출처·날짜, 선정 이유, 참고 자료와 시각적 관찰 |
| 컷 기획·생성 | 컷 카드 추가·복제, 프롬프트 미리보기·편집, 한 컷 또는 선택한 여러 컷 생성 | 고정 컷 ID·번호, 브리프, 참조 자산, 요청 상태, 실행 당시 프롬프트 |
| 검수·콘텐츠 풀 | 전체 보드와 원본 확대, 이전·새 버전 비교, 선택·보류, 색·장르·시즌으로 검색 | 원본 파일, 버전, 검수 메모, 채택 버전 ID, 태그 |
| 피드 편집·내보내기 | 여러 프로젝트의 컷을 3열 그리드에 배치, 순서 변경, 배열안 저장, JPG·보드·ZIP 다운로드 | 배열안 이름, 선택 버전 ID와 순서, 내보내기 시점의 목록 |

**관계** — 프로젝트 하나에 여러 주제와 컷이 속한다. 컷 하나는 여러 생성 버전을 갖고, 담당자는 그중 하나를 채택한다. 피드 배열안은 **버전 ID의 순서**를 저장한다. 같은 컷을 두 배열안에 담더라도 한쪽 편집이 다른 쪽에 영향을 주지 않는다. 배열에서 컷을 빼도 콘텐츠 풀에는 남는다.

**상태** — 생성 작업은 `대기 → 생성 중 → 성공 / 실패`로 추적한다. 검수는 버전별로 `검수 대기 / 채택 / 보류`를 기록한다. 새 버전이 생성되면 기존 채택본을 유지하고, 담당자가 교체했을 때 컷의 채택 버전을 갱신한다. 이미 저장한 피드 배열에는 당시 선택한 버전이 유지된다.

**생성 연결** — 현재 제작은 ChatGPT Image에서 수행했다. 웹 MVP에서는 이미지 생성 요청을 서버의 별도 모듈로 분리한다. 모델·사용 권한·요금은 웹 구현 시 확인한다. API 연결 전에도 프롬프트를 복사하고 ChatGPT에서 생성한 파일을 해당 컷에 올려 같은 검수·편집 과정을 진행할 수 있게 한다. 대량 생성은 컷별 작업 ID를 저장해 화면을 닫아도 상태를 복원하고, 실패한 컷만 재시도한다. 같은 요청을 두 번 눌러도 하나의 작업으로 처리한다.

## 5. Codex 구현 순서와 인수 기준

| 순서 | 구현 범위 | 실제로 확인할 시나리오 |
|---|---|---|
| 1 | 프로젝트 → 주제·무드보드 → 컷 브리프 | 08번 카드에서 Energy Orange를 선정한 이유, 레퍼런스 관찰, 음각 가공 지시를 다시 열 수 있다. |
| 2 | 생성 결과 업로드 → 검수 → 콘텐츠 풀 | 같은 컷의 두 버전을 비교하고 하나를 채택한다. 보류본도 수정 사유와 함께 다시 열 수 있다. |
| 3 | 3열 피드 편집 → 내보내기 | 03·08·15번을 두 가지 순서로 저장한다. 한 배열에서 08번을 빼도 다른 배열과 원본은 유지된다. 전체 20컷을 선택하면 번호가 붙은 JPG 20장과 인덱스 1장이 ZIP에 담긴다. |
| 4 | 서버 이미지 생성 → 배치 실행·재시도 | 20개 작업 중 한 컷이 실패해도 성공한 19장은 유지된다. 새로고침 후 실패 컷만 다시 실행하고 결과를 같은 컷에 새 버전으로 붙인다. |

첫 릴리스의 완료 지점은 담당자가 **주제 선정 이유부터 최종 이미지까지 추적하고, 콘텐츠 풀에서 원하는 컷을 조합해 다운로드하는 것**이다. 인스타그램 자동 게시와 영상 제작은 별도의 확장 범위로 둔다.

### Codex에 전달할 개발 시작 프롬프트

> 이 문서를 클라모아 인스타 콘텐츠 제작 웹사이트의 운영 명세로 사용해줘. 먼저 현재 저장소의 스택과 자산 저장 방식을 확인하고, 위 데이터 관계와 인수 기준에 맞춰 구현해줘. 첫 번째 동작 경로는 ‘프로젝트 생성 → 근거와 레퍼런스 등록 → 08번 컷 기획 → 이미지 2개 업로드·버전 비교 → 채택 → 피드 배치 → 내보내기’야. 이 흐름을 실제로 검증한 뒤 서버 이미지 생성과 컷별 재시도를 연결해줘. 기존 프로젝트 스킬이 있으면 `.agents/skills/create-clamoa-feed/SKILL.md`의 연출·로고·검수 기준도 반영해줘.
